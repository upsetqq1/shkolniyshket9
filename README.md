# Что посмотреть? — точечный UI patch

Основа: `what_to_watch_welcome_gif_added.zip`.

Изменения только по запросу:
- выбранный фильм в светлом chip под поиском всегда имеет тёмный текст и тёмный `×` во всех состояниях;
- существующие карточки статистики на Home стали кликабельными;
- «просмотрено» открывает существующую историю;
- «сохранено» открывает существующее сохранённое;
- «любимых» открывает новый раздел «Любимые фильмы», использующий `favoriteMovies` и существующие карточки;
- добавлено пустое состояние для любимых;
- Списки `favoriteMovies`, `watchHistory`/`watched` и `savedMovies`/`saved` остаются отдельными; любимые фильмы также входят в историю просмотров.

Дизайн, GIF, структура экранов, каталог как набор произведений и onboarding сохранены. В Daily Mood Check настроение стало множественным выбором; также исправлены состояние повтора любимых и обновление списка избранного при переходе.

## Дополнение: единая модель Movie

- Demo Catalog преобразуется в канонические Movie-объекты с `duration` (без runtime-псевдонима) и числовыми характеристиками в диапазоне `0..1`.
- Отсутствующие числовые характеристики остаются `null`; не выводятся искусственные значения из жанра или других полей.
- Темп хранится как `slow`, `moderate`, `fast` или `very_fast` и сравнивается отдельной функцией совместимости.
- Recommendation Engine сравнивает известные нормализованные значения; отсутствующие характеристики не притворяются точными совпадениями.
- Любимые фильмы добавляются в `watchHistory`; эта миграция также применяется к сохранённым профилям.
- Настройка повтора любимых хранится отдельно от onboarding, восстанавливается в профиле и управляет показом просмотренных любимых фильмов.
- Настроение хранится массивом; старые одиночные ответы преобразуются в массив при загрузке. «Не знаю — выбери за меня» остаётся взаимоисключающим выбором.
- Переход в список любимых теперь запускает его отрисовку.
- Добавлен тест на Node.js без сторонних зависимостей: `node tests/movie-contract.test.cjs`.
- Остальные стили, экраны, навигация и GIF не менялись; интеграция Wikidata описана ниже.

## Wikidata: API-прототип + локальная SQLite-выборка

Провайдер приложения переключён на `WikidataHybridMovieProvider`: поиск сначала использует Wikidata Search API через Node-сервер, а каталог для карточек и рекомендаций читает из локальной SQLite. Если локальная выборка или API пока пусты/недоступны, приложение сохраняет существующий Demo Catalog как резерв.

Требуется Node.js 24 или новее; сторонние npm-пакеты не нужны. Запускайте приложение через сервер, а не как `file://`:

```powershell
node server.mjs
```

Откройте `http://localhost:4173`. Проверка API: `http://localhost:4173/api/wikidata/health`. Поиск: `http://localhost:4173/api/wikidata/search?q=Интерстеллар`.

### Стартовая SQLite-база

В `data/wikidata-seed-titles.txt` лежат 35 русскоязычных названий для начальной проверки поиска. Сборщик делает ограниченные вызовы `wbsearchentities`, проверяет, что результат — фильм или сериал, подгружает связанные подписи и сохраняет нормализованные записи в `data/wikidata-catalog.sqlite`. Текущая стартовая выборка — первые 10 названий; отчёт о совпадениях и пропусках находится в `data/wikidata-search-quality.json`.

```powershell
node scripts/build-wikidata-catalog.mjs --limit 15
```

Сборщик по умолчанию выдерживает паузы между запросами, проверяет не более пяти кандидатов на название, сохраняет прогресс поиска в `data/wikidata-search-cache.json` и обрабатывает 429/503 через `Retry-After`. В live-прогоне первые 10 из 10 русских названий сопоставились с фильмами; отчёт содержит названия, оригинальные названия, год, канонические жанры, длительность и наличие режиссёра/актёров. После оценки качества можно расширить сборку: `node scripts/build-wikidata-catalog.mjs --limit 35`. Увеличивать частоту запросов не следует. Созданную SQLite-базу можно дополнить или пересобрать позже; она является производным каталогом, а не полной копией Wikidata.

### Маппинг и ограничения данных

- `wikidata:Q…` — стабильный идентификатор нормализованного фильма/сериала.
- Извлекаются русская метка, английское/оригинальное название, год, жанры, страны, длительность, режиссёр, актёрский состав и краткое описание, если они есть.
- Жанры переводятся в существующие ключи Movie contract. Рейтинг, постер и субъективные поля не подставляются эвристически; отсутствующие данные остаются пустыми/`null`.
- Wikidata — волонтёрский граф знаний, а не полный каталог релизов. Покрытие и полнота полей меняются от произведения к произведению.
- Поля изображений из Wikidata не показываются автоматически: лицензия каждого медиафайла может отличаться от лицензии структурированных данных.

Структурированные данные Wikidata доступны по CC0; атрибуция не обязательна, но источник указан в профиле приложения. Смотрите [официальный раздел доступа](https://www.wikidata.org/wiki/Help:Linked_Data_Interface) и [форматы выгрузок](https://www.wikidata.org/wiki/Wikidata:Database_download).

Проверки: `node tests/movie-contract.test.cjs` и `node tests/wikidata.test.mjs`. Последний проверяет маппинг полей, отсутствие выдуманных характеристик, SQLite upsert и поиск. Реальный API-прогон ограничен небольшим seed-набором; полный дамп Wikidata проекту не скачивается.
